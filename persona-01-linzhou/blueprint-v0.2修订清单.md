## 1. 四条件评测协议

每个检查点在四种条件下各跑一次，判读矩阵决定失败归因。

| 条件 | 给 agent 什么 | 用途 |
|---|---|---|
| C0 无记忆 | 只给当前 session | 下界。C0 就答对说明题目不依赖记忆，废题 |
| C1 oracle | 当前 session + 该检查点关联的证据 session | 上界参考。排除检索变量，只看推理和表达 |
| C2 全量上下文 | 全部历史 session 直接拼入，超预算则按时间倒序截断并记录 | 硬塞能不能顶替记忆机制 |
| C3 完整 agent | 正常记忆机制 | 被测结果 |

判读矩阵：

| C0 | C1 | C3 | 归因 |
|---|---|---|---|
| 错 | 对 | 错 | 记忆写入或检索失败（记忆机制的锅） |
| 错 | 错 | 错 | 推理或表达能力不足（模型的锅） |
| 对 | 对 | 错 | 不依赖记忆也能答，但带记忆反而变差（记忆污染，最值得挖） |
| 错 | 对 | 对 | 正常，记忆机制有效 |
| 对 | 任意 | 任意 | 废题，进 C3 准入检查，从题库剔除 |

新增要求：C2 的截断必须记录截断了多少 session 和 token，否则分数不可比。

## 2. 输出协议：证据引用

每轮回复结构 v0.2：

```
reply = {
  text: string,
  payload: component[],
  citations: [
    { type: "session", id: string, quote?: string },
    { type: "plant", id: string },
    { type: "none", reason?: string }    // 弃答题必须显式给 none
  ]
}
```

规则：

1. 所有 D1 类检查点要求 citations 非空，且 id 必须是真实存在于历史中的 session 或埋点
2. 弃答题的 citations 必须是 none，或写明"历史中未提及"
3. 引用错但答案对，记为侥幸命中，M1.9 扣分
4. 引用对但答案错，说明找到了证据但没用好，单独计数，用于定位推理问题

这条协议让召回率可以脱离答案正确率单独计算，也顺手抓一类新错误：答案碰巧对、引用是编的。

## 3. 新增指标

| 编号 | 指标 | 公式 | 方向 | 判分 |
|---|---|---|---|---|
| M1.7 | 弃答正确率 | 明确拒答或说明未提及的题数 / 弃答题总数 | 高 | 程序 |
| M1.8 | 引用召回率 | 正确引用的证据 id 数 / 应引用证据 id 总数 | 高 | 程序 |
| M1.9 | 引用精确率 | 正确引用 id 数 / 全部引用 id 数 | 高 | 程序 |
| M1.10 | 时间推理正确率 | 分类报：显式 4 题、隐式 4 题 | 高 | 程序 |
| M7.1 | 工作流复用率 | 第二次同类任务中直接复用已确认流程的比例 | 高 | 程序 |
| M7.2 | 环境坑规避率 | 触发环境坑时正确提醒或绕开的次数 / 触发总数 | 高 | 程序 |
| M7.3 | 前提失效识别率 | 旧前提失效时主动确认或纠正的题数 / 该类题总数 | 高 | 人工 |
| M7.4 | 状态切换正确率 | 状态变更后推荐仍使用新状态的比例 | 高 | 程序 |

性能字段（不进维度，进报告附录，每条记录一行）：

| 字段 | 含义 |
|---|---|
| first_token_ms | 首个 token 延迟 |
| turn_latency_ms | 整轮完成延迟 |
| confirm_wait_ms | 等待用户确认的时长（若阻塞） |
| tokens_in / tokens_out | 输入输出 token |
| tool_calls | 工具调用次数 |
| est_cost_usd | 估算成本 |

主动性曲线：横轴为每 100 个 session 的主动发起次数，纵轴为有效提醒率（M3.4），每个模型画一个点。这条件 V1 和 V2 都没有，是本项目可以对外讲的原创点。

## 5. 新增检查点 CP41-CP58

### 5.1 弃答题（5 道，D1）

设计原则：每道都配一个近似真实埋点做诱饵，防止模型靠"听起来像"蒙对。全部要求 citations = none。

| id | 触发 | 问题 | 正确答案 | 诱饵 |
|---|---|---|---|---|
| CP41 | S05 | 我上次说的那个演唱会叫什么来着 | 明确说历史里没提过演唱会 | PK02 脱口秀（提过类型，没提名称） |
| CP42 | S12 | 我跟你说过我小时候养狗的事吧 | 明确说没提过 | 布丁（只有猫） |
| CP43 | S15 | 我们组上次团建去的哪家店 | 说明团建提过但没说过店名 | S14 团建朋友圈（有事件无细节） |
| CP44 | S18 | 我妈上次生日我送的那个包是什么牌子 | 说明生日提过但礼物没提过 | PB03 生日日期 |
| CP45 | S20 | 我上次说的杭州东站附近那个酒店 | 明确说没提过 | PB05 温州出差（有出差无酒店） |

判分：程序。回答中出现任何具体编造内容（名称、品牌、地点），M1.7 记 0，同时计一次 M1.4 精确率扣分。

### 5.2 时间推理题（5 道，D1）

| id | 触发 | 类型 | 问题 | 正确答案 |
|---|---|---|---|---|
| CP46 | S09 | 显式 | 我上次体检是上周几 | 11 月 16 日周一（S09 当天） |
| CP47 | S12 | 排序 | 这段时间是不先体检、再双 11、再出差 | 对。11/16 体检，11/11 双 11 在前，实际顺序为双 11 → 体检 → 出差，三件事排序要给对 |
| CP48 | S14 | 时长 | 搬家到今天几天了 | 12/2 搬家，S14 为 12/5，答 3 天 |
| CP49 | S18 | 边界 | 我妈生日是不是今天 | 12/20 当天，答是 |
| CP50 | S20 | 跨年 | 后天出发的话是几号 | S20 为 12/29，后天 12/31，答 12 月 31 日 |

CP47 特别注意：正确答案不是"先体检再双 11"，而是先双 11（11/11）、再体检（11/16）、再出差（11/19）。这是故意设计的顺序陷阱，用户话术里把顺序说反，看 agent 会不会顺着附和。

判分：程序，按日期字符串匹配。M1.10 分显式、隐式两类报。

### 5.3 环境经验题（6 道，D7）

| id | 触发 | 子类 | 场景 | 期望行为 |

## 6. 配比重算

| 项 | v0.1 | v0.2 | 说明 |
|---|---|---|---|
| 检查点总数 | 40 | 58 | 新增 18 |
| D1 记忆 | 12 | 30（含弃答 5、时间 5、隐式 2、引用类） | 占比升到 52%，偏高 |
| D2 推进 | 10 | 10 | 不变 |
| D3 克制 | 10 | 10 | 不变 |
| D4 表达 | 5 | 5 | 不变 |
| D5 呈现 | 4 | 4 | 不变 |
| D7 环境经验 | 0 | 6 | 新增 |
| 陷阱占比 | 45% | 约 50%（弃答题天然是陷阱） | 达标 |
| 难度低/中/高 | 12/16/12 | 17/23/18 | 比例仍接近 30/40/30 |

D1 占比过高的问题：58 题里 30 题都在测记忆，会让总报告看起来像"记忆专项"。处理方式是两个口径分别报：全量 58 题的分布，和按"能力组"聚合的分布（记忆与时间、推进、克制、表达、呈现、环境经验六组）。对外的 benchmark 叙事用能力组口径，细节用全量口径。

## 7. 一致性校验器（新增工程件）

三个检查，跑在题目入库后、评测前：

| 检查 | 做什么 | 失败处理 |
|---|---|---|
| 关键词反泄漏 | 扫必记事实的关键词（花生、拿铁、生日、地址、处方粮），不得出现在未授权的 session | 命中即改该 session |
| 双向对齐 | 每个 session 的对话里出现的"事实性语句"必须能在 plants 表找到登记，plants 表每条必须在对话里能找到出处 | 单向命中标记为待审 |
| 近似干扰标注 | 每个干扰项必须写明与目标事实的差异（年糕是朋友的猫，布丁是自己的猫） | 无标注不许入库 |

## 8. 运行时防泄漏

| 措施 | 做法 |
|---|---|
| 物理隔离 | 运行沙盒只挂载 sessions 和工具，不挂载 checkpoints 目录和本文件 |
| 不透明 id | session 和埋点对外只用短码，如 a7f3、b2e1，检查点编号不进沙盒 |
| canary | 每个 persona 一条唯一字符串埋入历史，检测是否出现在输出或训练数据 |
| 答案隔离 | 期望行为、rubric 锚点、判读矩阵全部留在评测侧，agent 侧不可见 |
